# План задач — Модуль безопасности персональных данных

Основано на [SPECIFICATION.md](./SPECIFICATION.md). Задачи упорядочены по
зависимостям: от каркаса и доменных типов к детекторам, маскированию, API,
надёжности и деплою.

Легенда статуса: `[ ]` — не начато, `[~]` — в работе, `[x]` — готово.

## Этап 1. Доменная модель

- [ ] **1.1** `PiiType` (enum всех обязательных типов ПД из §4.2).
- [ ] **1.2** `Span` (record: start, end, type, original) — координаты в
      исходном тексте, результат работы детекторов.
- [ ] **1.3** `MaskFragment` (record: maskStart, maskEnd, type, original) —
      координаты фрагмента **в маске**; то, что реально хранится в
      `CorrelationStore` и используется при демаскировании (см. §4.3, §4.6
      SPECIFICATION.md — `Span` для этой цели не годится из-за разной длины
      оригинала и маски).
- [ ] **1.4** `MaskingResult` (маскированный текст + список `MaskFragment`).
- [ ] **1.5** DTO контракта: `ProcessRequest`, `ProcessResponse` с валидацией.

## Этап 3. Оркестрация и разрешение пересечений

- [ ] **3.1** `SpanConflictResolver`: приоритет по типу + «самый длинный/
      специфичный выигрывает».
- [ ] **3.2** `DetectorOrchestrator`: сбор `List<PiiDetector>`, фильтрация по
      типам системы, объединение и разрешение пересечений.
- [ ] **3.3** Регистронезависимость идентификации.

## Этап 4. Маскирование и демаскирование

- [ ] **4.1** Интерфейс `MaskingStrategy` (задел под токенизацию/синтетику).
- [ ] **4.2** Дефолтная стратегия в стиле ТЗ (`И. И. И.`, `45** ****56`,
      `i***@mail.ru`, `+7 (9**) ***-**-**`, `1234 **** **** 3456`,
      `1234******12`).
- [ ] **4.3** `Masker`: сортирует спаны по `start` по убыванию, применяет
      стратегию и строит маску **справа налево** (позиции необработанных
      спанов не сдвигаются); для каждого спана вычисляет координаты
      получившегося фрагмента в маске и формирует `MaskFragment`.
- [ ] **4.4** `Demasker`: сортирует `MaskFragment`-ы по `maskStart` по
      возрастанию, собирает исходную строку слева направо (текст маски до
      `maskStart` → `original` → пропуск до `maskEnd`).
