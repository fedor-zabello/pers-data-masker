## Проблема 1: чек-сумма отклоняет тестовый ИНН физлица

**Тест-кейсы:**
- `inn_01` — «ИНН: 770708389389» (`must_mask: true`)
- `inn_03` — «инн: 770708389389» (`must_mask: true`)

**Ожидание:** ИНН должен быть замаскирован.
**Факт:** не маскируется (FAIL).

**Причина:** `InnDetector.accept()` (строка 22) проверяет контрольные цифры.
Для `770708389389` обе контрольные цифры не сходятся (проверено скриптом),
поэтому фрагмент отклоняется. Тестовые данные не проходят строгую чек-сумму.

**Воспроизведение:**
```bash
cd blackBox && python3 test_runner.py --url http://161.104.16.21:8080/persmasker --skip-validation --skip-latency --skip-large
# в отчёте: [FAIL] [inn_card] inn_01: ИНН физического лица (12 цифр)
#           [FAIL] [inn_card] inn_03: ИНН в нижнем регистре
```

**Решение (выбрать один вариант):**
1. Ослабить чек-сумму для 12-значных ИНН (например, проверять только 10-значные,
   а 12-значные принимать по формату) — меньше ложных отказов.
2. Оставить строгую проверку, но исправить тестовые данные на валидный ИНН
   (например, `770708389389` → валидный). Это меняет тест, а не код.

Рекомендуется вариант 1: чек-сумма даёт ложные отказы на реальных данных.
