## Проблема 1: чек-сумма Луна отклоняет тестовый номер карты

**Тест-кейсы:**
- `card_01` — «Номер карты: 4276 1234 5678 9012» (`must_mask: true`)
- `card_02` — «Номер карты: 4276123456789012» (`must_mask: true`)
- `card_03` — «Номер карты: 4276-1234-5678-9012» (`must_mask: true`)
- `card_04` — «номер карты: 4276 1234 5678 9012» (`must_mask: true`)

**Ожидание:** номер карты должен быть замаскирован.
**Факт:** номер карты НЕ маскируется (проверено запросом к серверу).

**Причина:** `CardNumberDetector.accept()` (строка 20) требует прохождение
чек-суммы Луна. Тестовый номер `4276 1234 5678 9012` не проходит Луна
(проверено скриптом), поэтому фрагмент отклоняется.

**Важно (скрытая проблема):** тест-кейсы `card_01/02/03` проходят на сервере 21
НЕ потому, что карта замаскирована, а потому что слова «Номер карты»
маскируются как ФИО (ложное срабатывание `FullNameDetector`). Результат
`card_01`: `"Н. к.: 4276 1234 5678 9012"` — сам номер карты остался открытым.
Это маскирует реальную проблему.

**Воспроизведение:**
```bash
curl -s -X POST http://161.104.16.21:8080/persmasker/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"Номер карты: 4276 1234 5678 9012","payload_id":"probe"}'
# результат: {"result":"Н. к.: 4276 1234 5678 9012"} — номер карты НЕ замаскирован
```

**Решение (выбрать один вариант):**
1. Ослабить проверку Луна (например, принимать по формату 13–19 цифр без
   обязательной чек-суммы) — меньше ложных отказов на реальных данных.
2. Оставить строгую проверку, но исправить тестовые данные на валидный номер
   карты (проходит Луна). Это меняет тест, а не код.

Рекомендуется вариант 1: строгая Луна даёт ложные отказы на реальных номерах.

## Связанные тест-кейсы (проходят, но по ложной причине)

- `card_01/02/03` — PASS, но только из-за маскирования слов «Номер карты» как ФИО
- `card_full_01` «Карта 4276 1234 5678 9012, CVV 123, ...» — PASS (аналогично)
